# 예약 스케줄 걸기 (kkul-escape)

예약도우미 UI 서버(`ui/server.mjs`)가 예약 실행기(`ui/runner.mjs`)를 띄워 **오픈 시각까지 기다렸다가** 슬롯을 잡고,
신청서 입력까지 한다. 이 스킬은 화면 대신 `scripts/schedule.mjs` 로 같은 일을 한다.

## 원칙 (반드시 지킨다)

- **사용자 확인 없이 `start` 하지 않는다.** `plan` 결과(지점·테마·날짜·시간·오픈 시각·경고)를 보여 주고 "걸까요?"에 명시적으로 답을 받은 뒤 `--yes` 로 시작한다.
- **키이스케이프는 '예약하기' 자동 클릭이 기본 on** (사용자 결정 2026-11-16): reCAPTCHA 체크박스 자동 클릭 → 그림 문제는 사용자가 풂 → 토큰이 생기면(문제 없이 통과해도) 예약 정보 검증 후 '예약하기' 1회. 사용자가 원하지 않으면 `--no-auto-submit`.
- **그 밖의 최종 버튼 자동 클릭은 기본 off.** `--final-submit`(신청서형 최종 '예약하기/예약 확정') · `--auto-submit`(제로월드 '예약하기') 은 사용자가 그 동작을 콕 집어 요청한 경우에만 붙인다. 결제(단편선 '결제하기')는 이 스킬로 켜지 않는다.
- **개인 값(이름·연락처·입금자명)을 명령줄·대화·로그·파일에 쓰지 않는다.** 서버가 `ui/local.env`(git 제외) 또는 환경변수 `KEYESCAPE_NAME`/`KEYESCAPE_HP`/`KEYESCAPE_DEP` 에서 읽는다. 없으면 사용자에게 `ui/local.env.example` 을 복사해 직접 채우도록 안내한다(값을 대신 받아 적지 않는다).
- 서버 하나는 **동시에 1건**만 실행한다(같은 브라우저 탭). 두 건을 동시에 걸려면 포트를 나눈 서버를 하나 더 띄운다(아래 "여러 건").
- 끝난 작업을 '대기 중'으로 보고하지 않는다. 상태는 항상 `status` 로 확인한 뒤 말한다.

## 1. 준비 확인

```sh
curl -s --max-time 2 http://127.0.0.1:8899/api/log >/dev/null && echo 서버OK || echo 서버없음
curl -s --max-time 2 http://127.0.0.1:9222/json/version >/dev/null && echo 브라우저OK || echo 브라우저없음
test -f ui/local.env && echo local.env있음 || echo local.env없음      # 내용은 출력하지 않는다
```

- **브라우저(CDP :9222)** 가 없으면 `./unlock.sh` — 격리 크롬 프로필로 CDP 크롬을 띄운다(키이스케이프 디버거 차단 해제 포함).
  로그인이 필요한 사이트(단편선 `dps`, 네이버 `naver`)는 사용자가 그 크롬에서 **직접 로그인**해 두어야 한다.
- **서버(:8899)** 가 없으면 오픈 시각까지 맥이 잠들지 않게 `caffeinate` 로 띄운다 (세션이 끝나도 계속 돈다):
  ```sh
  cd ui && PORT=8899 CDP_PORT=9222 nohup caffeinate -i node server.mjs > server.out 2>&1 &
  ```
  (`sh ui/ui.sh` 는 CDP 확인 → 서버 → 브라우저 화면 열기까지 한 번에 한다. 화면이 필요 없으면 위 한 줄로 충분하다.)

## 2. 계획 (부작용 없음)

```sh
node scripts/schedule.mjs plan --site <키> --zizum <지점 번호|이름 일부> --theme <테마 번호|이름 일부> \
  --date YYYY-MM-DD --times HH:MM[,HH:MM…] [--person N]
```

- `--times` 는 쉼표로 여러 개 = **우선순위 순**. 출력의 `참고 시간표` 에서 고른다(아직 안 열린 날짜는 같은 요일 7일 전 시간표).
- 출력 마지막 줄 `PLAN_JSON` 의 `warns` 를 사용자에게 그대로 전한다(예약자 정보 없음, 시간표에 없는 시간, 이미 열린 날짜 등).
- 오픈 시각을 아직 모르면 실패한다 — 예: 제로월드 다이브 건대는 그날 **오픈 전에** `plan` 을 한 번 돌리면 서버 문구에서 시각을 읽어 기억한다. 사용자가 시각을 알고 있으면 `--open-at 2026-11-17T11:30:00+09:00` 으로 직접 줄 수 있다(확인 후).

| `--site` | 사이트 | 지점(`--zizum`) | 메모 |
|---|---|---|---|
| `keyescape` | 키이스케이프 | 백산방역(31)·후즈데어·STATION·LOG_IN 1/2·메모리컴퍼니·우주라이크·더오름·강남·홍대·부산·전주 | reCAPTCHA 체크박스 자동, 문제는 사람, 통과하면 '예약하기' 자동 · 10분 안 입금 |
| `zeroworld` | 제로월드 | 강남(4)·홍대(5)·다이브 건대(2) | 이미지 코드는 사람 입력 |
| `dps` | 단편선 강남 | 1곳 | 로그인 필요, 무통장입금 |
| `naver` | 네이버 예약 | `ui/naver-products.json` 상품 | 네이버 로그인 필요 |
| `rhe` | 토끼굴 홍대 | 1곳 | 매일 23:00 에 7일 뒤 오픈 |
| `jgb` | 지구별 | 대구(1)·홍대어드벤처(2)·홍대라스트시티(4) | 대구 2주 전 0시, 홍대 1주 전 22시 |
| `p33` | 플레이33 | 건대(1)·홍대(4)·대전(5)·수원(7)·티켓투(8) | 화면의 오픈 규칙을 읽음. 최종 버튼 자동 미지원 |
| `ptd` | 오늘의 한 페이지 강남 | 1곳 | 오픈 시각 공지 없음(자정 가정) |
| `oas` | 오아시스 뮤지엄 홍대 | 1곳 | 매일 자정 6일 뒤 오픈 |

## 3. 확인 → 시작

계획 요약을 보여 주고 확인을 받은 뒤:

```sh
node scripts/schedule.mjs start <plan 과 같은 인자> --yes
```

시작 후 사용자에게 알릴 것: 오픈 시각(KST), 그때 **브라우저 화면에서 사람이 할 일**
(키이스케이프 reCAPTCHA 문제 / 제로월드 이미지 코드 / 신청서형 최종 버튼 / 단편선·네이버 결제), 중단 방법.

## 4. 확인 · 중단

```sh
node scripts/schedule.mjs status [--lines 40]   # 실행 여부·대상·최근 로그 ([WAIT]/[POLL]/[HIT]/[PICK]/[CREATE]/[HANDOFF]/[ABORT]/[EXIT])
node scripts/schedule.mjs stop                  # 대기·실행 중단
```

- 서버 주소가 다르면 모든 명령에 `--server http://127.0.0.1:<포트>` (또는 환경변수 `KKUL_SERVER`).
- 실행기 출력은 `ui/runs.log` 에도 쌓인다(신청자 이름·연락처는 마스킹되어 찍힌다).

## 여러 건

같은 시각대에 두 건을 걸어야 하면 브라우저와 서버를 한 벌 더 띄운다:

```sh
CDP_PORT=9333 KEYESCAPE_PROFILE=/tmp/kkul-chrome-2 ./unlock.sh
cd ui && PORT=8900 CDP_PORT=9333 nohup caffeinate -i node server.mjs > server-8900.out 2>&1 &
node scripts/schedule.mjs start --server http://127.0.0.1:8900 … --yes
```

## 사이트별 주의

- 키이스케이프 메모리컴퍼니·STATION·후즈데어·백산방역: **같은 예약자 정보로 같은 테마 6개월 2회** 제한(사이트 공지). 백산방역은 같은 날짜 1회.
- 신청서형(토끼굴·지구별·플레이33): 최종 버튼이 곧 예약 생성 + 입금 의무다(토끼굴은 15분 안 가상계좌 입금, 미입금 시 자동 취소). 사람이 누르는 것이 기본.
- 실행기는 실패해도 **다시 누르지 않는다**(중복 예약 방지). 실패 로그가 나오면 브라우저에서 사람이 이어서 진행하도록 안내한다.
